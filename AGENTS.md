# Project delivery instructions

Read README.md, docs/04-project-status-and-decisions.md, and the relevant numbered baseline before making project changes. Original PDFs and docs/reviews are background inputs; the accepted baseline controls implementation.

The user authorizes lead-managed specialist delegation and autonomous routine project decisions. Delegate concrete independent packages with exclusive file ownership and acceptance criteria. The lead reviews actual deliverables and test evidence; an author cannot be the sole reviewer. Keep the backlog and decisions current. Do not ask the user which routine task to tackle next.

Keep the first release internal and cost-conscious. Use the approved PostgreSQL-only modular monolith. Do not add a paid service, runtime AI dependency, invasive collection field, or extra platform without a documented value and cost decision. Do not purchase or deploy to employee devices without the necessary company authority.

Use synthetic or approved anonymized data for development. Never place secrets or production employee data in prompts, source control, or test fixtures. Preserve unknown and conflicting evidence; never infer productivity or billing from input activity.

Real Windows behavior must be tested on Windows. Do not mark a gate passed from a mock, cross-platform simulation, or agent assertion alone. Report checks actually run, checks pending, and material limitations.

Keep original PDFs unchanged. Update source Markdown and regenerate the consolidated PDF when baseline documents change. No unattended execution is implied by these instructions.
